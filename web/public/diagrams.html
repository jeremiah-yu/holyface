Roles in this system

Database role codes stay admin, teacher, and student. Screens use Registrar, Professor, and Student. One REST API and MySQL database holyface_amgs.

Web Public site + professor gradebook
Mobile Student grades, ID, official card, study tools
Desktop Registrar files, accounts, locks, audit
API / MySQL PHP 8 REST, JWT, DepEd SUM

IPO — Input, Process, Output

School-paper IPO for Holy Face AMGS. Feedback is audit logs, period locks, and policy updates that go back into the next cycle.

INPUT

School and academic data

  • Username and password
  • WW / PT / QA scores
  • Class notes (PDF, Word, photo, max 15 MB)
  • School files and new accounts

Software and hardware

  • Web: PHP 8, React gradebook
  • Mobile: Expo / React Native
  • Desktop: Electron
  • Database: MySQL / MariaDB
  • API: PHP REST, JWT
  • AI: Gemini Flash-Lite (no identity)
PROCESS

System work

  • Authenticate: login and check role
  • Save: write records in MySQL
  • Compute: DepEd Order No. 8 s. 2015 SUM + transmutation
  • Lock: close grading periods
  • Issue: official report card when all finals are submitted
  • Study tools: extract notes, then plan / flashcards / quiz / chat with no name or student number
  • Maintain: file vault, accounts, audit

Data gathering

  • Class lists and enrollments
  • Policy acceptance
  • Registrar files and settings
OUTPUT

Holy Face Academic Monitoring and Grading System

  • Quarterly and final grades
  • Official report card snapshot
  • Digital ID and study tools
  • File vault and user directory
FEEDBACK

1. Overall system flowchart

Each person opens the matching app, then logs in to the same API. Student = mobile, professor = web, registrar = desktop.

2. Web flowchart — professor workspace

Professor login opens the gradebook SPA. Portal Login leaves AMGS and opens the official school portal. The professor does not issue the card; the API does when every assigned subject has submitted finals.

3. Mobile flowchart — student app

Expo student app. Uploaded notes are redacted; name, student number, photo, and contact are never sent to Gemini. File limit is 15 MB. Text that is not class notes is rejected.

4. Desktop flowchart — registrar console

Windows Electron app. Professors cannot encode grades here; they are sent to the web workspace. The registrar does not approve each grade. The official card appears after professors submit all finals.

5. Entity-relationship diagram

Chen-style logical ERD of holyface_amgs. students.lrn is labeled student number. teachers is the professor profile. Official cards are issued by the API for an enrollment, not approved one-by-one by the registrar.

8. DFD Level 2 — process 3.0 Encode and compute grades

Explosion of professor encoding. Computation follows DepEd Order No. 8, s. 2015. Weights and the transmutation table are stored in MySQL.

  1. Percentage Score = (total score ÷ total highest possible score) × 100 (SUM; absent/excused skipped)
  2. Weighted Score = Percentage Score × component weight
  3. Initial Grade = WW + PT + QA weighted scores
  4. Quarterly Grade = transmutation table lookup
  5. Final Grade = average of semester quarters, rounded
  6. Official card = JSON snapshot when every assigned subject has submitted finals
